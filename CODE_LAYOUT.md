# Code layout

`extract/`, `analysis/`, and `fig_gen/` hold this project's code, organized by
role rather than by which pipeline it came from:

- `extract/` -- reads raw/source data and writes tidy intermediate outputs
  (the `extract_*.py` scripts, loaders, provenance).
- `analysis/` -- computes statistics/metrics/derived quantities from those
  tidy outputs (responder tests, group categorization, chi-squared metrics,
  RSA, recovery-time analysis, etc.).
- `fig_gen/` -- draws figures from analysis outputs (`compose_*.py`,
  `make_panels_*.py`, `panels/`, plotting scripts, shared style assets).
- `notebooks/` -- exploratory Jupyter notebooks (not part of the pipelines
  above).

`data/` is now pure data + rendered figures (git-ignored, regenerated by
`sync_*.sh`) -- no code lives there any more.

**These are reference copies, not a runnable working copy.** Each file's
internal `sys.path`/relative-path logic assumes it still sits in its
*original* location inside its source repo, which this reorg does not
rewrite. To actually run something, use it from its home repo:

- `context-value-RNNs/results/transfer/{code,combined,reversal/code}/...`
- `neuronal-representations/results/transfer/{extract,figures}/...`

**Naming**: a file keeps its original name unless two source pipelines used
the identical filename, in which case both get a suffix identifying which
pipeline they came from (`_combined`, `_experimental`, `_reversal`/`_study`)
-- e.g. `fig_gen/panels/decoding_combined.py` vs. `decoding_experimental.py`,
or `fig_gen/compose_combined.py` vs. `compose_experimental.py`. Everything
else is unrenamed.

**Not moved on purpose**: `data/rnns/reproducibility/` and
`data/rnns/reversal/reproducibility/` (the `cxval` modeling package,
training/inference scripts, and sweep-launcher shell scripts) are left in
place -- they're the model-training library and reproducibility material,
not extraction/analysis/fig-gen pipeline code, so none of the three
categories above fit them.

**Regenerating this layout**: `sync_all.sh` calls `sync_rnns.sh` /
`sync_experimental.sh` / `sync_combined.sh` (data only, code subfolders
excluded) and then `sync_code.py` (code only, flattened + renamed per
`sync_code.py`'s `MAPPING`). Re-run any time the source repos change --
`sync_code.py` only copies files that actually changed, and warns if a
new cross-pipeline filename collision needs a rename added to `MAPPING`.
